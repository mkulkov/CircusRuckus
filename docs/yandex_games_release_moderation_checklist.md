# Чек-лист релизной проверки игры перед модерацией Яндекс Игр

Универсальный шаблон для проекта с локализацией, рекламой и внутриигровыми покупками. Перед каждым релизом сверяйте формулировки и лимиты с актуальными [требованиями Яндекс Игр](https://yandex.ru/dev/games/doc/ru/requirements).

## 1. Карточка релиза

- [ ] Версия сборки, дата, commit/build hash и ответственный за проверку зафиксированы.
- [ ] Проверяемые платформы, разрешения, ориентация и список поддерживаемых языков указаны.
- [ ] Проверяется именно production-сборка, а не debug/development/preliminary build.
- [ ] Состав экспортного архива просмотрен; в архив не попали логи, тестовые сцены, исходники и временные файлы.

## 2. Локализация — требование 8.2.3

- [ ] Для каждого локализуемого поля в кабинете заполнен соответствующий язык.
- [ ] Все экранные тексты, сообщения, названия кнопок, настройки, HUD, пауза, результаты и ошибки переведены.
- [ ] Тексты в графике, видео, скриншотах, обложке и иконках соответствуют языку поля.
- [ ] В каждом языке нет строк на языке по умолчанию, ключей локализации, обрезанного текста, `???` и отсутствующих символов.
- [ ] Переключение языка проверено после перезапуска и после инициализации SDK площадки.
- [ ] Проверены длинные переводы, переносы, RTL/специальные символы (если язык поддерживается).
- [ ] Офер покупки, цена, валюта и сообщения об оплате локализованы или отображаются в формате, который требует площадка.

## 3. Production-состояние и технические артефакты — требование 1.15

- [ ] Удалены технические иконки, заглушки, placeholder-графика и временные надписи.
- [ ] Удалены debug/FPS/лог-панели, координаты, служебные кнопки, тестовые меню и dev-навигация.
- [ ] В интерфейсе нет кнопок тестовой покупки, тестового начисления или обхода прогресса.
- [ ] Release-флаги отключают разработческие функции; скрытые debug-маршруты недоступны.
- [ ] Проверены первый запуск, главное меню, все настройки, игровой цикл, пауза, экран результата и повторный запуск.
- [ ] В production-архиве нет признаков предварительного тестирования.

## 4. Объявление ИАП — требование 1.13.6

- [ ] Список товаров в кабинете полностью совпадает с товарами, которые доступны в игре.
- [ ] Для каждого товара проверены точный ID (`{product_id}`), тип, назначение и постоянство entitlement.
- [ ] Неактивные, удалённые и тестовые товары не отображаются игроку.
- [ ] Если в кабинете нет активных товаров, магазин и точки покупки скрыты или корректно сообщают о недоступности.
- [ ] В игре нет покупок, которые не заявлены в кабинете.

## 5. Цена и портальная валюта — требования 1.13.4 и 1.13.2

- [ ] Офер отображает цену и валюту для каждого товара до нажатия кнопки покупки.
- [ ] Цена и валюта получаются из каталога площадки, а не зашиты в клиенте.
- [ ] Не показывается неполный офер: пока каталог не загружен, цена отображается как loading/недоступна.
- [ ] Формат, символ и подпись валюты соответствуют текущим правилам площадки и выбранной локали.
- [ ] После изменения цены в кабинете клиент получает и показывает новое значение без выпуска с устаревшей ценой.

## 6. Покупка и применение результата — требование 1.13.5

- [ ] Нажатие на товар открывает платёжный сценарий именно для нужного `{product_id}`.
- [ ] Успешная покупка выдаёт заявленный результат ровно один раз.
- [ ] Для постоянного товара entitlement применяется сразу и сохраняется между запусками.
- [ ] Отмена, отказ, недоступность товара, сетевой сбой и повторное нажатие обрабатываются без ложного начисления и зависшего loading.
- [ ] Во время активной покупки повторный запрос блокируется или безопасно дедуплицируется.
- [ ] Пользователь видит понятный результат: покупка применена, отменена или не выполнена.

## 7. Восстановление покупок и реклама

- [ ] При старте игры выполняется восстановление ранее выданных прав через API площадки или его эквивалент.
- [ ] Право сохраняется после перезапуска, обновления страницы и прерывания платёжного окна.
- [ ] Повторное восстановление не выдаёт дубликаты и не сбрасывает уже применённое право.
- [ ] Для permanent remove-ads реклама отключается после восстановления права.
- [ ] После remove-ads отключены все предусмотренные рекламные форматы: баннеры, межстраничные и внутриигровые показы.
- [ ] Исключения (например, обязательный стартовый или rewarded-формат) оставлены только если они разрешены актуальными правилами площадки.

## 8. Видео, скриншоты и другие материалы

- [ ] Каждый файл загружен в правильное локализованное поле (`{locale}`, например `ru` или `en`).
- [ ] Язык текста и озвучки в ролике совпадает с языком поля; в ролике нет посторонней локализации.
- [ ] Видео показывает реальный игровой процесс, а не редактор, debug-интерфейс или технические иконки.
- [ ] Проверены актуальные требования площадки к разрешению, ориентации, длительности, кодеку и размеру файла.
- [ ] Каждый ролик полностью декодируется от начала до конца; нет чёрных кадров, рассинхронизации и обрывов.
- [ ] Скриншоты, обложка и иконка не содержат технических символов, placeholder-текста и неверного языка.
- [ ] Для каждого файла сохранены исходный путь, фактические размеры/формат и контрольная сумма.

## 9. Автоматические и статические проверки

- [ ] Проект импортируется и загружается без ошибок парсера и отсутствующих ресурсов.
- [ ] Выполнены релевантные unit/integration/smoke-тесты.
- [ ] Выполнена headless-проверка запуска сцены/ресурсов, если это доступно для проекта.
- [ ] Проверены экспортные настройки и содержимое финального архива.
- [ ] Для медиа проверены фактические размеры, длительность, кодек и полный decode (например, `ffprobe`/аналогом).
- [ ] Сняты свежие runtime-скриншоты для каждого языка, магазина и состояния покупки.
- [ ] Отдельно записаны проверки, которые нельзя подтвердить локально: кабинет, sandbox/тестовый аккаунт, реальная оплата, устройство и модерация.

## 10. Ручной pre-submit прогон

- [ ] В кабинете заполнены все локализованные поля и опубликован актуальный draft.
- [ ] В кабинете активны ровно те товары, которые проверены в игре.
- [ ] Выполнены сценарии: успешная покупка → перезапуск → восстановление → отмена/ошибка → повторная проверка.
- [ ] Проверено поведение на чистом запуске и на аккаунте с уже выданным правом.
- [ ] Проверены минимум один desktop/browser и одно мобильное устройство, если они входят в целевой релиз.
- [ ] Все найденные замечания закрыты, повторно проверены и имеют ссылку на доказательство.
- [ ] Только после этого нажата отправка на модерацию.

### Правило закрытия

Каждый `FAIL` должен иметь исправление и повторную проверку. `BLOCKED` допустим только с указанием внешней проверки, которая ещё не выполнена (например, sandbox или кабинет); такой пункт нельзя считать закрытым перед отправкой.
