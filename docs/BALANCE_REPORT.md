# Баланс после проверки на ПК — 2026-10-09

Исторические результаты для 60-секундного раунда. Следующим запросом раунд сокращён до прежней длительности раунда и цели уменьшены пропорционально; текущие значения — в SPEC.md и data/levels. Ниже приведённые агрегаты не являются проверкой прежней длительности баланса.

Причина: пользователь не успевал набрать очки на втором уровне. Предыдущая модель с неизменной быстрой реакцией не представляла этот сценарий.

В обоих сравниваемых прогонах используются одинаковые seeds 1–100, фактические SpawnDirector/GameController и шаг 0.02 с. Решение по каждой цели задерживается на reaction × random(0.65,1.55); тапы сериализованы. Профили: ideal 0.12 с/0% пропусков, confident 0.28 с/5%, novice 0.48 с/15% и одна ошибка по Bomb, cautious 0.95 с/8%; idle и random spam. Это предположения модели, не измерения игроков.

Визуальный цикл заменён моделью: hittable примерно через 0.18 с, занятость после попадания 1.096 с, после побега 0.82 с. Fairness читает все занятые типы. Пропуск задан на всю цель; модель не симулирует точность наведения, неправильное распознавание и реальный touch. Поэтому комфорт проверяется человеком.

Каждый прогон: 5418 раундов, повтор seed 42 совпал на девяти уровнях, Godot exit 0. До изменения cautious L2: 8/100 побед; после: 100/100.

Количество побед из 100. Время цели усредняется только по достигшим её раундам; выполнение целей не завершает раунд досрочно. Clock продлевает раунды L7–9, максимум до 90 с. Idle/random spam не выигрывают ни на одном уровне.

Реальная headless Gameplay-сцена L2 seed=42 дополнительно проверена без ускорения: распознавание/перемещение 0.95–1.35 с после hittability, реальный таймер 60 с и tweens. Результат: 270/140 очков, цель за 29.96 с, три жизни, победа. Тест `tests/desktop_balance_runtime.gd` проверяет маршрутизацию головы к коробке и использует отдельное сохранение. Он не заменяет ручную игру мышью.

Воспроизведение: `python tools/tune-loop.py`, затем Godot `--headless --path . --script res://tests/balance_simulation.gd`; для реальной сцены `--script res://tests/desktop_balance_runtime.gd`. Текущие агрегаты: `balance_simulation.json`, предыдущие: `balance_before_desktop_retune.json`.

Физическое устройство и реальный VK после изменения баланса не проверялись; старый VK debug-архив относится к прежним значениям.
