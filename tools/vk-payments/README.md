# Покупка «Отключить рекламу» через VK

Товар: `remove_ads`, цена **299 голосов VK**. Это голоса, а не рубли.
Клиент вызывает `VKWebAppShowOrderBox`. Право выдаётся только по подписанному
серверному уведомлению VK и хранится в SQLite для восстановления на другом устройстве.
База является источником истины; клиентское `ads_removed` не подтверждает покупку VK.

Пошаговая инструкция для действующего VPS с VPN, nginx и Let's Encrypt:
[DEPLOY_VPS.md](DEPLOY_VPS.md), домен `vk-games-shop.mkulkov.ru`.

## Локальная проверка

Нужен Node.js 24 или новее; устанавливать npm-зависимости не требуется.
Из корня проекта:

```powershell
node --test tools/vk-payments/server.test.mjs
node tests/vk_bridge_test.mjs
```

Тесты используют вымышленные ключи и временную базу. Они проверяют подписи,
299 голосов, повторную доставку заказа, возвраты, восстановление после перезапуска,
разделение test/live, отмену/ошибку оплаты и снятие паузы.
Это локальные проверки, не настоящие платежи VK.

## Размещение сервера

1. Разместите папку `tools/vk-payments` на сервере с Node.js 24+, постоянным диском
   и HTTPS reverse proxy. Статический VK Hosting не исполняет этот сервер.
2. Скопируйте `.env.example` в `.env`. Внесите защищённый ключ приложения в
   `VK_APP_SECRET` только на сервере. Ключ никогда не передаётся в Web-сборку,
   репозиторий, URL или командную строку.
3. Оставьте `VK_APP_ID=54768735`, `VK_REMOVE_ADS_PRICE=299`,
   `VK_PAYMENT_MODE=test`. Для VK Hosting можно оставить `VK_ALLOWED_ORIGINS`
   пустым: сервер принимает только stage/prod домены с 12-символьным hash,
   соответствующие указанному `VK_APP_ID`. Для внешнего HTTPS-хостинга внесите
   точный origin (без пути и завершающего `/`), несколько origin через запятую.
4. В `VK_DATABASE_PATH` укажите путь на постоянном диске. Сохраняйте базу вместе
   с WAL/SHM корректным SQLite backup; не копируйте отдельно активный файл базы.
   Запускайте один экземпляр приложения, не используйте эфемерный serverless-диск.
5. Из папки сервера выполните `npm start`. Настройте автоматический перезапуск
   процесса и HTTPS proxy на `127.0.0.1:8787`. Proxy должен сохранять POST-тело
   и `Origin`, пропускать OPTIONS и не кешировать API. Не записывайте тела запросов
   и параметры запуска в access/error logs; настройте ограничения частоты запросов.
6. В проекте Godot установите `monetization/vk/payments_base_url` на HTTPS-адрес
   этого сервера без завершающего `/`, например `https://payments.example.org`.
   Сервер предоставляет `/vk/payments/catalog`, `/vk/payments/entitlements`
   и `/vk/payments/callback`. Пересоберите `Web - VK Mini Apps`.

Пока адрес пустой или каталог недоступен, предложение покупки скрыто.
Для авторизации клиент передаёт подписанные параметры запуска VK в POST-теле.
Сервер проверяет `sign`, `vk_app_id`, `vk_user_id` и `vk_ts` (срок 24 часа).
Если запуск слишком старый, повторно откройте игру через VK.

## Кабинет VK и тест до модерации

1. В приложении `54768735` откройте **Платежи → Подключение**.
2. Укажите адрес обратного вызова:
   `https://ВАШ-СЕРВЕР/vk/payments/callback`, версию уведомлений **5.132**
   (обработка возвратов). Отдельный каталог VK не нужен: описание и цену товара
   возвращает обработчик `get_item_test` / `get_item`.
3. В поле «Тестировщики платежей» выберите нужного администратора и сохраните.
4. Разместите новый Web-билд в Dev, откройте игру внутри VK под тестировщиком.
   Проверьте цену **299 голосов VK**, отмену покупки (реклама сохраняется), затем
   успешную покупку (баннер и межстраничная реклама отключаются).
5. Перезагрузите игру и откройте её на другом устройстве под тем же VK-аккаунтом:
   право должно восстановиться. Под другим аккаунтом право отсутствует.
6. Проверьте повтор уведомления: прежний `app_order_id`, без повторного начисления.
   Подписанный `refunded` отменяет право, если нет другого оплаченного заказа.
   Игра обновляет право при возврате фокуса/видимости или перезапуске.

В актуальной документации VK тестовые платежи не списывают голоса и не проверяют
баланс. Наличие 299 голосов на тестовом счёте не требуется.

## Переход к реальным платежам

После модерации и размещения игры в каталоге платежи обычных пользователей
становятся реальными; пользователи из списка тестировщиков остаются в тестовом
режиме. Перед этим переключите сервер на `VK_PAYMENT_MODE=live` и перезапустите его.
Этот сервер намеренно принимает уведомления только своего режима: в live
`*_test` отклоняются. Для тестировщиков после публикации используйте отдельный
Dev-билд и отдельный тестовый сервер. Не направляйте live и test билды в один endpoint.

Тестовые и реальные заказы имеют отдельные пространства ключей в SQLite.
Переключение на live не переносит тестовое отключение рекламы. Локально сохранённое
право также не переносится: при каждом запуске VK проверяет серверный реестр.
Повторная доставка `chargeable` после `refunded` не возвращает право.
Если сервер недоступен, новая покупка не начинается и право не выдаётся.
Обрыв связи после оплаты можно исправить повторным входом: право восстановится
по сохранённому серверному заказу без повторного списания.

## 2026-10-01 — Прогресс VK / Одноклассников

Сервер добавляет `/vk/payments/progress` (POST, form-urlencoded). Клиент передаёт
исходные подписанные параметры запуска. Отсутствие поля `progress` читает запись,
наличие — принимает JSON прогресса. Подпись, app ID, пользователь и срок параметров
проверяются до чтения/записи. Нельзя передать неподписанный `vk_client=ok`.

SQLite автоматически создаёт таблицу `progress`; существующая таблица платежей
не изменяется. Ключ записи: соцсеть + app ID + user ID. Прогресс не зависит от
режима test/live платежей. Уровни объединяются, очки/комбо сохраняют максимум:
поздний запрос со старого устройства не откатывает достижения. Настройки звука
используют последнее принятое значение. Поле `ads_removed` из прогресса не выдаёт
права покупки и не сохраняется как оплаченная привилегия.

Добавьте `OK_APP_ID` в окружение сервиса, если в ОК используется отдельный ID.
Это публичный идентификатор из кабинета, не ключ. Если переменная не задана,
принимается только существующий `VK_APP_ID`. Не добавляйте произвольные ID в
список: сверяйте подписанный запуск приложения с настройками кабинета.
`VK_APP_SECRET` остаётся только на сервере. Для собственного ОК-хостинга внесите
точный HTTPS origin в `VK_ALLOWED_ORIGINS`; wildcard не используется.

На reverse proxy должен проходить путь `/vk/payments/progress` под существующим
префиксом игры так же, как catalog/entitlements. Перед обновлением сервера сделайте
резервную копию SQLite. Разверните `server.mjs`, перезапустите существующий сервис,
затем разместите новую Web-сборку. Старая сборка и VK платежные пути совместимы.

Локальные файлы клиента теперь разделены по соцсети, app ID и user ID. Старый общий
локальный файл VK автоматически не переносится: его владельца нельзя надёжно
определить. Яндекс и Android продолжают использовать свои существующие сохранения.
Сетевой сбой сохраняет локальный прогресс; повторная инициализация/отправка выполняется
через 30 секунд активной работы. После входа на другом устройстве прогресс читается
с сервера. Серверные записи не используются для проверки честности результатов.

### Платежи ОК — реализованная схема

Реализация сверена с предоставленными PDF официальной документации VK
«Продажа виртуальных товаров в Одноклассниках» и «Обработка платёжных уведомлений
в Одноклассниках», а также с алгоритмом подписи https://apiok.ru/dev/examples/payment.
Клиент использует `VKWebAppShowOrderBox`, затем проверяет право через сервер.
Для ОК мобильный ответ SDK может предшествовать commit платёжного GET callback:
клиент опрашивает entitlement до 10 раз с интервалом 1,5 секунды. При ошибке/таймауте
право не выдаётся; оно восстановится после подтверждения сервера при следующем
запуске или возврате фокуса. Старый VK-only сервер не может выдать ОК право:
новый клиент требует `site=ok` в ответах каталога и entitlement.

В окружении сервиса дополнительно задайте:
- `OK_APP_ID` — отдельный ID приложения ОК;
- `OK_APP_PUBLIC_KEY` — публичный ключ приложения ОК;
- `OK_APP_SECRET` — секрет для GET callbacks ОК; пустое значение использует общий
  `VK_APP_SECRET`, только если кабинет подтверждает одинаковый ключ;
- `OK_PAYMENT_MODE=test` либо `live`;
- `OK_REMOVE_ADS_PRICE` — выбранная владельцем положительная целая цена в ОКах.

Цена не пересчитывается из голосов VK автоматически. Пока ID, публичный ключ,
режим или цена не заданы, каталог ОК пуст и покупка скрыта.

В кабинете укажите два РАЗНЫХ URL под существующим префиксом игры:
- «URL для платёжных уведомлений ВКонтакте»: `.../vk/payments/callback`;
  здесь POST `get_item` с подписанным `site=OK` возвращает цену в ОКах.
- «URL для платёжных уведомлений Одноклассников»: `.../ok/payments/callback/test`
  в тестовом режиме или `.../ok/payments/callback/live` в рабочем.
  Это GET `callbacks.payment`; сервер сверяет декодированную MD5-подпись,
  `application_key`, пользователя, товар и сумму, сохраняет транзакцию в SQLite
  и только потом отвечает JSON `true`. Ошибки содержат `Invocation-error`.

Nginx должен проксировать И `/vk/payments/`, И `/ok/payments/` под префиксом
`/games/circusrucus`. Не включайте журналирование query-строк callback: они содержат
подписи и идентификаторы. Не меняйте остальной nginx/VPN без необходимости.
Тестовые/рабочие записи изолированы, режим входит в URL callback, чтобы поздний
запрос из sandbox после переключения не выдавал рабочие права.

Подписки не реализованы: игра продаёт только `remove_ads`. Неизвестные товары,
валюты и непустые subscription attributes отклоняются. Повторные транзакции
идемпотентны. Для возвратов официальная документация задаёт
`payment.refundUserPayment`; после подтверждённого возврата нужно локально вызвать
`service.recordOkRefund(transactionId, userId)` на сервере. Метод не доступен через
HTTP. Отметка возврата постоянна: поздний повтор оплаты не восстанавливает право.
Автоматическое выполнение возвратов и сверка внешних возвратов не реализованы;
не придумывается недокументированный формат callback возврата.

Дополнительные проверки: `node tests/ok_bridge_test.mjs` и
`node --test tools/vk-payments/server.test.mjs`.
Развёртывание на VPS, реальные параметры запуска ОК, два физических устройства,
платёжный sandbox и модерация пока НЕ проверены. Новая SQLite-таблица `ok_orders`
создаётся автоматически, существующие VK-заказы не изменяются.

### Проверка реального запуска OK (2026-10-02)

Современный контейнер OK передаёт VK ID в `vk_app_id`, отдельный ID приложения в
`vk_ok_app_id`, ID пользователя OK в `vk_ok_user_id` и `vk_ts` в миллисекундах.
Сервер проверяет подписанную пару ID приложения, нормализует время только для OK
и ищет платёжное право по ID пользователя OK. Старый формат запуска также поддерживается.
Все эти параметры остаются частью проверяемой HMAC-подписи. Изменение режима в .env
не переключает платёжный интерфейс площадки в sandbox: в OK нужен собственный
тестовый режим разработчика. Тестовые права изолированы от live.
